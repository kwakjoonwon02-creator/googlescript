# TETRA.GS 실시간 릴레이

Apps Script는 페이지 서빙과 **계정·레이팅·랭킹·전적**을 계속 맡고,
이 프로세스는 **지연에 민감한 부분만** 맡습니다 — 방, 매칭, 보드 상태,
채팅, 관전.

릴레이 없이도 게임은 그대로 동작합니다(폴링). 릴레이를 붙이면 상대 보드가
300~600ms 대신 **50ms 남짓**으로 갱신됩니다.

## 코드 사본이 없습니다

릴레이는 `../src/Rooms.gs` 와 `../src/Matchmaking.gs` **그 파일을** 읽어서
VM 컨텍스트에 올립니다 (`lib/sources.js`). 저장소만 메모리 구현으로 바꿔
끼우고, 인증과 정산은 훅으로 주입합니다.

구현이 하나뿐이므로 두 배포가 어긋날 수 없습니다. 방 규칙을 고치면 양쪽에
동시에 반영됩니다.

```
릴레이가 로드하는 것          Apps Script에만 있는 것
  Rooms.gs                     Players.gs   계정
  Matchmaking.gs               Glicko.gs    레이팅
                               Ranks.gs     랭크
                               Match.gs     정산·전적
                               Leaderboard.gs
```

## 실행

### 1. Apps Script에서 켜기

편집기에서 `setupRelay("wss://내-릴레이-주소")` 를 한 번 실행합니다.
비밀키가 생성되고 실행 로그에 찍힙니다.

### 2. 릴레이 띄우기

```bash
cd relay
npm install
RELAY_SECRET=<위에서 나온 값> \
SETTLE_URL=<웹앱의 /exec URL> \
PORT=8080 \
npm start
```

| 환경변수 | 필수 | 설명 |
|---|---|---|
| `RELAY_SECRET` | ✅ | Apps Script와 공유하는 HMAC 비밀키 |
| `SETTLE_URL` | 권장 | 웹앱 `/exec` 주소. 없으면 랭크 결과가 시트에 안 남습니다 |
| `PORT` | | 기본 8080 |

`GET /health` 로 상태를 확인할 수 있습니다.

### 3. TLS

Apps Script 페이지는 `https` 로 서빙되므로 브라우저가 `ws://` 를 막습니다.
**`wss://` 가 필요합니다.** Fly.io·Railway·Render 같은 곳은 TLS를 앞단에서
붙여주므로 `RELAY_URL` 에 `wss://` 주소만 넣으면 됩니다. 직접 운영한다면
앞에 리버스 프록시를 두세요.

## 보안 모델

비밀키 하나로 양방향을 인증합니다.

**들어오는 쪽 — 티켓.** Apps Script가 부트스트랩 때 서명된 1시간짜리
티켓을 발급합니다. 티켓에는 플레이어 id·이름과 매칭에 쓸 레이팅 값이
들어 있어, 릴레이는 스프레드시트를 읽을 필요가 없습니다. 소켓의 티켓이
유일한 신원이고, **클라이언트가 페이로드에 적어 보내는 id는 덮어씁니다.**

**나가는 쪽 — 정산.** 경기가 끝나면 릴레이가 `doPost` 로 결과를 보냅니다.
서명은 **전송되는 JSON 문자열 그 자체**에 대해 계산합니다. 반대쪽에서
다시 직렬화하면 키 순서에 따라 서명이 달라질 수 있기 때문입니다.

비밀키가 없으면 릴레이 경로 전체가 꺼지고 폴링으로 동작합니다.

## 한계

- **상태는 메모리에만** 있습니다. 재시작하면 진행 중인 방이 사라집니다
  (계정·레이팅은 시트에 있어 무사합니다).
- **인스턴스 하나** 기준입니다. 여러 개로 늘리려면 방을 공유 저장소로
  옮겨야 합니다 — `lib/store.js` 를 Redis로 바꾸면 되는 구조입니다.
- **부정행위는 여전히 막지 못합니다.** 시뮬레이션은 클라이언트에서 돌고
  릴레이는 중계·판정만 합니다. 막으려면 서버가 엔진을 직접 돌려야 합니다.
